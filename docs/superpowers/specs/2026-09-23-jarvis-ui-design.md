# 贾维斯悬浮窗 UI 设计（v1）

> 日期：2026-09-23 · 实现同步：2026-09-24（阶段 2）
> 范围：`macos/` 原生悬浮窗的全部 UI，以及 UI 需要的 host 数据接口。托管、审批 relay、口播控制及任务进度已接通；后续功能状态以 backlog 为准。
> 参考交互稿：`.superpowers/brainstorm/82021-1790147640/content/`（`states-v5.html` 形象动效、`dock.html` 贴边、`hover.html` / `badge.html` / `space.html` Hover 与角标、`mini.html` 快速回复）。

## 1. 目标与原则

- 风格：钢铁侠贾维斯，全息青色、粒子构成、强科技感。
- 不阻碍使用：默认半透明、贴边可收成细带、按需出现、点击穿透透明区域。
- 精简：整个产品只有"形象 + 一个输入条"，其余内容按需贴附在输入条上，不做独立大面板。
- 全部显隐行为可在设置里自定义。

## 2. 形象

### 2.1 几何

形象直径 120pt。以外半径 r₂ = 1 归一化：

| 区域 | 半径范围 |
|---|---|
| 核心圆 | 0 – 0.40 |
| 小环 | 0.40 – 0.70 |
| 大环 | 0.70 – 1.00 |

核心半径 = 小环内半径，小环外半径 = 大环内半径，两环厚度相同（0.30）。不画任何辅助线，形状完全由粒子分布呈现。

### 2.2 粒子

- 每个粒子是独立个体：各自的弹簧常数 k ∈ [10, 28]、阻尼比 ζ ∈ [0.55, 0.9]（c = 2√k·ζ）、轨道速度、闪烁相位、尺寸（0.7–1.3 倍）。
- 目标位置用向日葵（黄金角）分布在目标区域内生成；状态切换时按角度排序匹配，粒子沿径向移动；出发时间按角度错开 0–0.3s 并加 0–0.25s 随机，形成"一颗颗出发"的效果。
- 非待机状态下，核心圆内不留任何粒子。
- 渲染：加法混合的发光点精灵，底下一层暗色径向衬底（rgba(4,8,18,0.55)）保证在浅色背景上可见。
- 颜色：青 `#5CE1FF`、琥珀 `#FFC24D`、红 `#FF5F5F`。

### 2.3 粒子档位

设置里提供三档，界面上只写名字、不写数量：

| 档位 | 粒子数 |
|---|---|
| 极简 | 300 |
| 精简 | 600 |
| 默认 | 900 |

### 2.4 状态

参数以 `states-v5.html` 为准（`STATES` 表），原样移植。

| 状态 | 触发 | 粒子表现 |
|---|---|---|
| 待机 | 无任何活动 | 聚在核心圆内缓慢游走 |
| 等待消息 | 输入条打开等你打字，或在等托管会话回结果 | 全部散到小环，各自缓慢绕行 |
| 思考 | 贾维斯在推理、还没开口 | 小环内高频随机换位，速度越快越亮 |
| 说话 | 口播中 | 在两环之间往复呼吸，幅度跟随语音包络 |
| 需要你处理 | 有审批或提问 | 推到大环、变琥珀色、双拍心跳脉冲 |
| 出错 | 贾维斯离线/出错，或有托管会话失败未查看 | 小环内抖动、红色、闪烁 |

**状态合成规则**：先取"状态色"：贾维斯自身离线或出错为红；否则有待处理为琥珀；否则有托管会话失败未查看为红；否则为青。再取动作：说话 > 思考 > 状态色为红时"出错"、为琥珀时"需要你处理" > 等待消息 > 待机。因此"有审批时贾维斯在口播"表现为琥珀色的说话动作，颜色不会丢；角标数字也按同一优先级取（§5.1）。

### 2.5 减少动态效果

跟随系统"减少动态效果"（设置可关）：粒子静止在各自目标位置，状态切换改为 0.3s 淡入淡出，需要你处理用缓慢的透明度起伏代替心跳位移。

## 3. 显隐

| 场景 | 默认行为 |
|---|---|
| DSH Desktop 在前台（bundle id 前缀 `ai.deepseek.dsh.desktop`） | 不透明度 100% |
| 其他应用在前台 | 不透明度 35% |
| 鼠标进入形象 80pt 范围 | 随距离渐显，悬停时 100%；离开后 0.25s 淡回 |
| 需要你处理 / 出错 | 不透明度至少 85%（在隐藏场景里仍然隐藏） |
| 全屏应用或全屏视频 | 隐藏 |
| 调度中心（Mission Control） | 隐藏 |
| 应用程序启动器（macOS 26 取代启动台的全屏 Apps 界面） | 隐藏 |
| 用户列表中的应用在前台 | 隐藏 |

- 隐藏时渲染停止（0fps），显示时恢复。
- 输入条打开时强制可见且不透明；快捷键可在全屏、启动器、指定应用隐藏状态中打开输入，关闭后立即重新执行以上隐藏规则。
- 调度中心：窗口 `collectionBehavior` 改为 `[.canJoinAllSpaces, .transient, .fullScreenAuxiliary]`，由系统负责隐藏。
- 全屏检测：前台应用、Space 切换、以及定时轮询时检查。判定依据是 `CGWindowList` 中存在属于前台应用、layer 0、铺满当前屏幕的窗口。要排除 DSH 自己的截图遮罩等覆盖层。
- 应用程序启动器检测（spike 结论见 §11）：`CGWindowList` 中出现属于 Spotlight（`com.apple.Spotlight`）且 layer > 0 的大面积可见窗口即视为启动器打开。Dock 进程的全屏窗口不作为信号：显示桌面、切换空间时它也会出现，会把形象误藏。切换结果写入 `panel-debug.log`，便于调优。

## 4. 拖拽与吸附

- 拖动阈值 4pt；松手时离边缘 30pt 以内吸附。共 8 个吸附位（4 角 + 4 边），距离相同时角优先。
- 只在当前屏幕的可见区域内活动：不压菜单栏、刘海、Dock。Dock 只挡住它实际占的那一段（按图标数估算长度），同一条边上 Dock 以外的角落仍可吸附。
- 位置按显示器分别记忆；显示器不在时回退到主屏右上角。
- **贴边收起（B 方案）**：吸附后形象化为贴边的一条粒子细带（边上约 5pt 宽、96pt 长；角落是两边各 78pt 的 L 形）。状态在细带上同样可见：琥珀色脉冲、说话时细带厚度呼吸、出错红色闪烁。
- 鼠标移到细带上，完整形象滑出；离开 0.4s 后收回。
- 单击形象打开快速回复（§6）；右键打开菜单（§7）。

## 5. Hover 层与角标

### 5.1 角标

- 只有一个角标，**颜色永远跟随形象当前颜色**，自身不带状态色。
- 数字：有待处理时显示待处理数；否则有失败时显示失败数；否则显示运行中的托管会话数；都为 0 时只剩未读小圆点（没有未读就不显示角标）。贾维斯自身离线时数量未知，不显示角标。
- 有未读的新结果时，角标右上角加一个白色小圆点。
- 新结果和失败项在展开对话或点 ↗ 回 DSH 后视为已查看（调用 `/jarvis/read`），小圆点和失败带来的红色随之清除。
- 平时位置在形象上方，偏向读数会展开的那一侧（§5.3）。
- 贴边收成细带时，角标显示在细带末端。

### 5.2 按钮

悬停时形象变为不透明并进入待命动效（与输入条打开时相同；说话、思考、待处理、失败照常显示），两个按钮沿形象外侧弧线弹出（环形 HUD，依次延迟 0.05s）：

| 按钮 | 行为 |
|---|---|
| 声音 | 说话时为"暂停口播"，平时为"静音 / 取消静音" |
| 对话记录 | 打开快速回复，并直接展开对话 |

"发消息"不单独做按钮，单击形象即是。每个按钮悬停时显示文字提示。

### 5.3 读数与空间约束

悬停时角标淡出，换成明细读数：运行中 / 待处理 / 新结果 / 失败，数量为 0 的项目省略。

布局规则（纯函数，输入是形象位置和当前屏幕可见区域）：

1. 按钮放在水平空间更大的一侧（朝屏幕内侧），以水平方向为中心上下对称，两个按钮间隔 30°、半径 88pt。弧线最多只张开 ±30°（将来加按钮也不超过），这样贴上下边时也碰不到菜单栏或 Dock。
2. 读数优先放在按钮对面，以三行列表沿弧线排开；对面空间不足 110pt 时，改成一条单行胶囊：形象在上半屏时放在下方，在下半屏时放在上方，从靠边一侧往屏幕内侧延伸。
3. 所有元素必须落在可见区域内，否则退到下一种布局；实在放不下时读数不显示，不允许遮挡。

## 6. 快速回复（核心交互）

不再有"面板"。单击形象弹出一行输入条，光标已就位。输入条贴在形象旁，水平方向朝屏幕内侧，与形象垂直居中对齐（靠近上下边时向内平移）。待处理卡片和对话都放在输入条的同一侧：垂直空间更大的一侧（上半屏向下、下半屏向上）。卡片紧贴输入条，对话在卡片外侧。

### 6.1 输入条

- 结构：`[发送目标 ▾] 输入框 [⌃ 展开对话] [发送]`。
- 发送目标：第一项“贾维斯”是直接对话、不转发；其余**只列托管会话**，保留会话标题，名字前圆点表示会话运行态。底部“＋ 交给贾维斯…”展开未托管候选，选择后纳入托管；托管行悬停出现“移出”按钮。
- 标题右侧另显示任务徽标：`open` → “进行中”、`judging` → “判断中”、`unsatisfied` → “未完成”（琥珀色）。无任务、已结或过期任务不显示；徽标不被压缩，长标题截断时仍保留徽标和快捷键。
- 徽标悬停显示 summary：优先使用判断的缺少项，否则是用户原话前 30 个 Unicode 字符。任务进度与会话运行态、未读/失败角标分别表达，不混用。
- 默认目标是上次用过的目标，失效时回退“贾维斯”。点目标或按 Tab 打开列表切换，⌘1–⌘9 直接选。按显式目标发送，不自动猜测目标。
- 回车发送，Shift+回车换行（最多 3 行）；Esc 关闭。
- 发送后输入条收起，形象旁显示"已发给 hammer"，1.5s 后消失；形象进入等待消息状态。发送失败时输入条不收起，保留文字，目标标签下显示一行红色错误。
- 点击输入条以外的地方也会关闭；未发送的文字保留到下次打开。

### 6.2 待处理卡片

- 有审批或提问时，卡片按时间顺序堆在输入条上方（最多显示 3 张，其余折叠为"还有 N 件"）。
- 审批卡：`会话名 · 请求执行`、命令（等宽字体，host 展示最多 300 字符）、`批准` / `拒绝`。DSH 原窗口同时可答，先答者生效；审批结果先返回，随后异步写 HTML 记录，写失败不影响用户决定。
- P0：仅 `canAlwaysAllow: true` 的审批卡显示次级按钮 `总是允许（此工作区）`，提问卡或缺少/非法字段时隐藏。点击发送 `decision: "always"`，本次批准后异步保存工作区预设；高危或无法可靠判定的操作由 host 隐藏按钮并拒绝伪造请求。默认逐次审批，P1 是否放行由 DSH 设置页的自动审批模式决定。
- P1：悬停时显示最近五条自动审批，包含会话标题、操作摘要和安全/灰区/中风险等级；仅带 P0 预设身份的记录显示 `撤销此规则`。撤销按完整三元组删除，404 视为已移除，其他错误显示并可重试；已执行操作不会撤回。无预设依据的自动批准只显示记录。口播字幕与该悬停卡片同时出现时放在卡片内，避免遮挡。
- 提问卡：`会话名 · 问题`、选项按钮、`我来回答`。
- 点选项直接提交；卡片右上角 ↗ 回到 DSH 查看完整上下文。
- 点"我来回答"时，输入条目标切到该会话，并标记为"回答中"，发送内容作为答复提交。
- 形象在需要你处理状态时单击，输入条和卡片一起弹出，目标自动切到最早那张卡的会话。

### 6.3 对话展开

- 点 ⌃（或 Hover 的"对话记录"按钮）后，对话记录按 §6 开头的方向展开，最高 360pt，超出滚动，远离输入条的一端渐隐，没有标题和边框。
- 记录随发送目标切换：选“贾维斯”读取它的对话，选 worker 读取该会话的对话。我的消息靠右，助手消息靠左；若有 routedTo，在气泡底部标一行 `→ hammer：…`。host 默认保留最近 20 条会话气泡，客户端显示最近 20 条。
- 工具调用不逐条显示。
- 展开状态会被记住，下次打开沿用。

## 7. 右键菜单与设置

右键形象弹出系统菜单，只有两项：`设置…` / `退出`（退出后下次 DSH 启动时由插件重新拉起）。声音控制只在 Hover 按钮里，不在菜单里重复。

设置是一个独立的原生窗口（SwiftUI `Form`），保存在 `~/.dsh/jarvis/panel.json`：

P0 新增“审批规则”区域，每次打开从 host 刷新，可按工具、完整工作区路径和指纹查看并删除预设，展示创建/到期日期、加载和错误状态。此列表存于插件的 `memory/preferences/approvals.json`，不写入 `panel.json`；删除发送完整三元组，404 时重新加载，失败保留原列表供重试。

| 分组 | 项 | 默认 |
|---|---|---|
| 快捷键 | 呼出输入框（点击后按新组合，Esc 取消） | `⌃⌥J` |
| 显示 | DSH 在前台时不透明度 | 100% |
| | 其他应用在前台时不透明度（15–100%） | 35% |
| | 鼠标靠近时渐显 | 开 |
| | 需要处理或出错时保持醒目（至少 85%） | 开 |
| 隐藏 | 全屏应用或视频时隐藏 | 开 |
| | 调度中心中隐藏 | 开 |
| | 应用程序启动器中隐藏 | 开 |
| | 这些应用在前台时隐藏（从正在运行的应用里添加） | 空 |
| 动效 | 粒子档位：极简 / 精简 / 默认 | 默认 |
| | 跟随系统"减少动态效果" | 开 |
| 位置 | 贴边时收成细带 | 开 |
| | 重置位置 | — |

修改即时生效，不需要保存按钮。

全局快捷键使用 Carbon `RegisterEventHotKey` 的独占注册，不使用全局键盘监听或辅助功能权限。输入关闭时打开并聚焦；输入已聚焦时关闭；输入打开但焦点在别处时重新聚焦。录制支持修饰键加字母、数字、F1–F20 及常见控制键，标签按 ANSI 物理键位显示，与当前输入法无关。至少一个修饰键；无效组合不保存，注册失败显示“快捷键被占用”并保留旧组合。`panel.json` 的 `hotKey` 缺省或无效时使用默认组合。快照模式不注册快捷键。

## 8. Host 数据接口

所有路由须通过 loopback 与 token 校验（不满足返回 403）；面板发送 bearer，host 当前也兼容 query token（SEC1 尚未收紧）。Desktop 还需 runtime.json 中的 rendererHeader（若有）。面板每次请求重读 runtime.json，宿主重启换端口/token 后可重新连接。

`GET /jarvis/state` 返回实时快照，以下为字段示意（`|` 表示可选值）：

```json
{
  "agentId": "…",
  "managed": ["…"],
  "speaking": false,
  "activity": "idle | awaiting | thinking | speaking",
  "error": null,
  "voice": {
    "speaking": false, "muted": false,
    "source": "jarvis | session", "sessionId": "…",
    "paused": false, "queued": 0
  },
  "counts": { "running": 2, "pending": 1, "unread": 1, "failed": 0 },
  "sessions": [{
    "id": "…", "title": "hammer", "workspace": "project-name", "managed": true,
    "status": "running | waiting | done | failed | idle", "unread": false,
    "task": { "status": "open | judging | unsatisfied", "summary": "补齐回归测试" }
  }],
  "pending": [{ "id": "…", "kind": "approval | question", "session": "…", "title": "…", "detail": "rm -rf node_modules", "note": "…", "choices": ["保留旧表", "直接替换"], "canAlwaysAllow": false }]
}
```

- `sessions` 包含所有可见、未归档 worker，排除 Jarvis 自己；`managed` 区分托管目标与候选。`workspace` 是 cwd 的目录名，缺失时省略。标题不强制添加“贾维斯-”前缀。
- `task` 仅包含未结且未过期任务；`summary` 可省略。面板兼容无 task 的旧快照，遇到未知 status、非对象 task 或非字符串 summary 时忽略该 task，不影响其他会话数据。
- `counts.running/unread/failed` 只统计托管 worker；pending 为当前全部待答项数量。`session.status` 表示运行/结果态，独立于 `task.status`。
- `voice.source/sessionId` 按当前口播信号可选返回；`paused/queued` 是 voice-mini 的暂停/排队状态。`activity=idle` 且输入条打开时客户端本地显示等待消息。
- `autoApprovals` 可选，形如 `[{id,session,title,tool,command,tier:"safe|grey|medium",at,rule?:{fingerprint,tool,workspace}}]`；at 为毫秒时间戳。插件仅保留本次运行中最新五条，面板按时间排序、按 id 去重并再限五条；缺失/非法字段或损坏条目不影响其余快照。预设从任一入口删除后，host 移除对应记录的 rule 字段。

| 路由 | 参数 / 请求体 | 响应与用途 |
|---|---|---|
| `GET /jarvis/sessions` | 无 | `{managed:[id]}`；无旧 monitoring 字段，面板使用 state 而不读此接口 |
| `GET /jarvis/wait` | `?since=<version>&timeout=<毫秒>` | `{version}`；版本变化即返回，否则等到超时（默认 1000ms，上限 25000ms） |
| `POST /jarvis/managed` | `{session, managed: boolean}` | `{managed:[id]}`；纳入或移出，纳入不存在/不可见目标返回 404，缺少参数返回 400；移出终止任务并清理旧续做问题 |
| `GET /jarvis/messages` | `?session=<worker-id>` 可选 | 默认 Jarvis 对话；指定 id 读取可见 worker，未知目标 404；正常返回 `{messages:[…], count}`，会话尚不可用时返回 `{messages:[], error:"no session"}` |
| `POST /jarvis/input` | `{text, session?}` | `{ok:true}`；不传 session 为直接对话，传 session 为指定目标转发；空输入 400、Jarvis 未就绪 503 |
| `POST /jarvis/pending/answer` | `{id, decision?: "allow" \| "deny" \| "always", choice?: string, text?: string}` | 成功 204；答案非法或不允许创建预设时 400，已失效/不存在 404 |
| `GET /jarvis/approval-rules` | 无 | `{rules:[{fingerprint,tool,workspace,createdAt,expiresAt?}]}`；返回未过期预设 |
| `POST /jarvis/approval-rules/remove` | `{fingerprint,tool,workspace}` | 精确删除，成功 204；非法三元组 400，不存在 404 |
| `POST /jarvis/voice` | `{action: "pause" \| "resume" \| "skip" \| "clear" \| "mute" \| "unmute"}` | 成功 204，未知动作 400；静音/取消静音与 voice-mini 队列控制 |
| `POST /jarvis/read` | `{session?}` | 204；清除指定会话或全部未读与失败标记 |
| `POST /jarvis/open` | `{session}` | 204；当前把 DSH 切到前台，尚不保证定位指定会话 |

消息有稳定 `id`、`role`、`text` 和可选 `routedTo`（会话 id）、`toolCalls`，UI 仅渲染文字与转发标记。选择目标后同时切换消息查询；慢请求不得覆盖新目标的记录。

刷新循环：获取快照/消息后调用 `/jarvis/wait`，可见时等待 1 秒、隐藏时 5 秒；变化提前唤醒，到时也会重新读取快照（任务台账变化不要求每次推进版本）。断线时按相同间隔重试。已实现 HTTP 长轮询，SSE 尚未采用。

**演示模式**：设置环境变量 `JARVIS_DEMO=1` 启动时，客户端不连 host，用内置假数据循环播放所有状态、角标、卡片，用于 UI 验收和截图。

## 9. 原生实现结构

在现有 `macos/` SwiftPM 包内重构。可测的逻辑都做成不依赖 AppKit 的纯类型：

| 模块 | 职责 | 可单测 |
|---|---|---|
| `Orb/ParticleSim` | 粒子状态、目标分配、弹簧步进；可注入随机种子 | 是 |
| `Orb/OrbStateResolver` | 从快照算出动作状态、颜色、角标 | 是 |
| `Orb/OrbRenderer` | `MTKView` + Metal 实例化点精灵、加法混合；自适应帧率 | 否 |
| `Layout/Placement` | 吸附目标、贴边细带形状、Hover 层与输入条布局（§5.3） | 是 |
| `Window/OrbPanel` | 形象窗口（固定尺寸，含角标余量） | 否 |
| `Window/OverlayPanel` | Hover 层 / 输入条 / 卡片 / 对话窗口，尺寸跟随内容，可成为 key 以接收输入 | 否 |
| `Window/VisibilityController` | 汇总前台应用、全屏、启动器、设置，输出目标透明度与是否隐藏；判定逻辑为纯函数 | 判定部分是 |
| `UI/*` | HoverLayer、QuickBar、PendingCard、History、SettingsView（SwiftUI） | 否 |
| `Model/PanelModel` | ViewModel：快照、输入、目标选择、发送、回答、错误状态 | 是 |
| `Model/SettingsStore` | 读写 `panel.json`，缺省值与越界修正 | 是 |
| `Net/JarvisClient` | 现有客户端扩展新路由；协议化以便测试替身 | 是（替身） |

- 两个窗口的原因：展开内容时不改变形象窗口的尺寸，避免旧版展开/收起时的抖动。
- 鼠标跟踪改为事件驱动（全局 + 本地 `mouseMoved` 监听），去掉 60Hz 定时器；拖动期间才用高频更新。
- 帧率：待机 30fps，其余状态 60fps，隐藏 0fps。
- `Package.swift` 增加测试目标 `JarvisPanelTests`（XCTest），可执行目标拆出一个库目标 `JarvisPanelCore` 以便测试。增加 `macos/build.sh` 产出 `macos/jarvis-panel`。
- 性能预算：900 粒子待机时 CPU < 2%、内存 < 40MB（现状约 5–6% CPU、28MB）。

## 10. 测试

- **ViewModel（`PanelModel`）按"等价类 + 边界值 + 异常路径"三段式**：
  - 等价类：发给贾维斯 / 发给会话；审批批准 / 拒绝；选项回答 / 文字回答；静音 / 暂停口播。
  - 边界值：空白输入不发送；多行文本原样发送；0 个托管会话时目标列表只剩"贾维斯"；上次目标已不在托管集时回退到"贾维斯"；待处理 0 / 3 / 4 张（折叠）；⌘9 超出列表长度。
  - 异常路径：host 未运行（无 runtime.json）、HTTP 403/500、超时、发送失败保留文字、回答已失效的待处理项、快照字段缺失（旧 host）。
- U2 任务进度：等价类覆盖三种标签与缺少项摘要；边界覆盖无任务、已结、30 字摘要和长标题；异常覆盖未知状态与损坏 task。快照 `18-targets-task-state` 已留存于 `docs/superpowers/evidence/2026-09-24-u2-task-state/18-targets-task-state.png`，验证徽标、长标题截断及快捷键。
- `OrbStateResolver`：优先级与颜色组合的全表测试。
- `Placement`：中间 / 四边 / 四角 / 菜单栏 / Dock / 刘海 / 多显示器，断言所有元素落在可见区域内且互不重叠。
- `ParticleSim`：固定种子下非待机状态核心圆内粒子数为 0；收敛后所有粒子落在目标区域内；档位切换数量正确。
- `SettingsStore`：缺省、越界值修正、损坏文件回退默认。
- 手动验收：演示模式下逐项核对本文档各节，另在真实全屏视频、调度中心、应用程序启动器下验证隐藏。

## 11. 风险与 spike

| 风险 | 处理 |
|---|---|
| 应用程序启动器（macOS 26）没有公开的检测接口 | 已 spike：`/System/Applications/Apps.app` 打开时出现 Spotlight（聚焦）进程的窗口；旧日志中另有 Dock（程序坞）全屏窗口，但它在显示桌面时也会出现、导致形象在桌面上被误藏，已移除，只保留 Spotlight 信号 |
| 全屏误判（截图遮罩、无边框全屏窗口） | 排除表 + 仅判 layer 0 + 必须属于前台应用 |
| 透明区域点击穿透 | OverlayPanel 只覆盖内容实际尺寸；形象窗口按鼠标是否在粒子圆内切换 `ignoresMouseEvents` |
| 非激活面板里的文字输入 | 沿用现有 `canBecomeKey` 做法，spike 验证输入法（中文 IME）候选窗位置正确 |
| 在 DSH 中打开指定会话 | 接口能力未确认；拿不到时退化为把 DSH 切到前台 |

## 12. 不在本版范围

- 语音输入（STT）。
- 事件推送（SSE），当前使用 HTTP 长轮询。
- 播报字幕（U1）、自动答疑（J7）；已有托管、审批 relay 和口播控制均使用真实 host 接口。
- 预渲染动图备选方案（实时渲染已满足性能预算）。
